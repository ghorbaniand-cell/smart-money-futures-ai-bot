GFTSH V3.26 — گزارش عملکرد ۲۴ ساعته ۲۸ ولت

محتویات:
- gftsh_10_wallet_observer.mjs: نسخه کامل ورکر با گزارش خصوصی عملکرد ۲۴ ساعته

رفتار گزارش:
- در هر چرخه، Fillهای ۲۴ ساعت اخیر هر ولت بررسی می‌شوند.
- تعداد ورودهای جدید به پوزیشن (بدون شمردن افزایش حجم/میانگین‌گیری به‌عنوان ورود جدید) برای هر ولت شمرده می‌شود.
- برد/باخت و سود تحقق‌یافته از closedPnl در Fillهای بسته‌شدن محاسبه می‌شود؛ رتبه‌بندی بر اساس سود تحقق‌یافته است.
- فقط ولت‌هایی که در بازه ورود یا بسته‌شدن داشته‌اند در جدول رتبه‌بندی نمایش داده می‌شوند؛ ولت‌های بدون معامله گزارش را متوقف نمی‌کنند.
- گزارش هر ۲۴ ساعت واقعی از زمان ارسال موفق گزارش قبلی تکرار می‌شود، نه صرفاً یک‌بار در هر روز تقویمی UTC.
- اگر درخواست API برای یکی از ولت‌ها خطا بدهد، گزارش آن چرخه ارسال نمی‌شود تا داده ناقص به‌اشتباه فعالیت صفر تلقی نشود؛ چرخه بعد دوباره تلاش می‌کند.
- پنجره سیگنال‌ها همچنان از GFTSH_LOOKBACK_MIN استفاده می‌کند؛ منطق هشدار، فهرست ۲۸ ولت، باند ۱٪ و حالت READ-ONLY تغییر نکرده‌اند.
- ROI تقریبی است: سود تحقق‌یافته تقسیم بر notional مربوط به Fillهای بسته‌شدن، نه بازده واقعی حساب.
- Win rate بر اساس Fillهای بسته‌شدن دارای closedPnl محاسبه می‌شود و الزاماً نرخ موفقیت معاملات مستقل نیست.
- Fillهای فاقد closedPnl جداگانه شمرده می‌شوند و برایشان سود/زیان حدس زده نمی‌شود. PnL شناور پوزیشن‌های باز در سود تحقق‌یافته لحاظ نمی‌شود.

تنظیمات لازم:
- TELEGRAM_TOKEN یا TELEGRAM_BOT_TOKEN
- TELEGRAM_CHAT_ID
- HYPERLIQUID_API_URL (اختیاری؛ پیش‌فرض رسمی Hyperliquid)

نصب:
فایل gftsh_10_wallet_observer.mjs را در همان مسیر فعال مخزن GitHub جایگزین کن. اجرای node --check با موفقیت انجام شده است. پس از اولین چرخه موفق کامل، گزارش اولیه ارسال می‌شود؛ گزارش بعدی ۲۴ ساعت پس از آخرین ارسال موفق خواهد بود.

محدودیت:
تعداد ورودهای جدید از Fillهای برگشتی Hyperliquid تشخیص داده می‌شود. سود تحقق‌یافته بر اساس closedPnl گزارش می‌شود، نه PnL شناور پوزیشن‌های هنوز باز. اگر API سقف پاسخ برای Fillهای قدیمی‌تر داشته باشد، داده‌های بازگشتی API مبنا هستند.
